# 手机调用电脑 GPU 反推

电脑启动后会在后台自动开启 HTTPS 共享。「设置 → 电脑反推配对」中可以复制固定地址和配对码，也可以手动停止或重新开启。手机先在「设置 → 电脑反推配对」填写地址和配对码并点击「保存并测试连接」，然后在反推页选择「电脑 GPU 反推」；以后重开会恢复保存的地址、配对码和模式。已经保存过连接的旧版本升级后会默认恢复电脑 GPU 模式；原来的在线反推仍可选择，其选择也会保存。结果仍可复制或导入正面提示词。

手机继续使用原来的 VPN，不需要安装或连接 Tailscale，也不下载模型。电脑需要登录 Tailscale，账号允许 Funnel，并保持 NAI Studio 和电脑运行。每次启动软件自动开启共享，启动过程不加载模型、不阻塞窗口；配置失败会提示原因，可在设置里的配对项手动重试。退出软件只停止本地服务，保留 Tailscale 的固定转发配置，以免每次重开都重新登记公网 DNS；软件关闭时不能处理反推请求。手动点「停止共享」会关闭 8443 的公网转发，下次启动自动重新开启。地址和配对码会复用，只要电脑的 Tailscale 域名和应用密钥存储没有更换，手机无需重复填写。首次使用本地模型仍需下载约 5 GB 的模型与 CUDA 环境，已有缓存可复用。

路径：手机 HTTPS → Tailscale Funnel → 电脑 127.0.0.1:18965 → 现有 PixAI Tagger v1.0 CUDA 管线。它不依赖手机与电脑在同一网络，也不要求手机占用 VPN 接口。HTTPS 由 Tailscale 提供证书；账号首次启用时可能要求管理员允许 Funnel。公开地址受 Tailscale Funnel 的服务可用性及带宽限制，电脑睡眠、断网或退出软件时不可用。

首次启用后，官方说明公网 DNS 最多需要约 10 分钟生效（[DNS propagation](https://tailscale.com/docs/features/tailscale-funnel)）。这时手机可能显示域名无法解析，请保持电脑共享开启再重试。验收公网链路时必须关闭手机 Tailscale，避免 MagicDNS 将该名称解析为内网 100.x 地址而产生误判。

系统 DNS 对 `.ts.net` 地址解析失败时，反推客户端会通过 Cloudflare 的 HTTPS DNS 备用查询地址，仅发送公开主机名，不发送配对码或图片。其他域名不使用该备用查询，系统正常解析时也不会使用；HTTPS 证书验证和配对鉴权照常进行。

## 配对与文件处理

- 所有接口均要求随机的 256 位配对密钥，包括连接检查。配对码只通过用户主动点击复制；电脑 SecretStore 和手机 Android Keystore 保存凭据，不写入 Git 或日志。仅把配对码给自己的设备。
- 服务只监听本机回环地址，不打开 LAN 监听或 Windows 防火墙端口；拒绝覆盖 8443 上的其他 Tailscale 服务。
- 上传单张图片不超过 16 MiB、2500 万像素；同时只处理一个远程任务，连接线程数有上限。客户端禁止携带密钥跟随 HTTP 重定向，只接受 HTTPS。
- 图片写入临时文件供本地模型处理，正常成功或失败后删除。异常断电可能留下系统临时文件。请求取消会停止手机等待，但电脑已开始的 GPU 推理可能继续完成，然后清理图片。
- 使用现有 CUDA 管线，不自动回落 CPU；显存不足或 CUDA 不可用会显示错误。连接检查只检查共享接口，不预加载模型或证明显卡已就绪。

HTTP 服务使用 NanoHTTPD 2.3.1，以兼容现有 Windows 精简 Java 运行时；许可见 [NanoHTTPD-LICENSE.txt](third-party/NanoHTTPD-LICENSE.txt)。构建桌面部署时必须同步该依赖 JAR 和 launcher classpath。

## 验证（2026-10-04）

桌面全套 JVM 测试通过：573 项，7 项可选集成测试跳过，零失败。此前显式启用的实际 CUDA 集成测试已验证直接反推和 HTTP 上传反推结果一致。鉴权、无效图片、临时文件删除、GPU 忙时拒绝第二个请求，以及 DNS 回退范围均有回归测试。

已在当前 Windows 精简运行时中的应用共享服务上验证手机访问真实公网 IPv4 Funnel 中继：手机关闭 Tailscale、恢复原 VPN 后，通过 USB 执行的 HTTPS 请求完成鉴权、图片上传和 GPU 标签返回；未跳过 TLS 证书校验。测试显式指定公网中继地址，避免系统缓存的内网解析造成误判。另外验证手机可以直接访问备用 HTTPS DNS 并获取公网 A 记录。应用页面内的选图、复制和导入操作仍需用户手动验收。

Android 单元测试和 local release 构建通过：554 项，零失败、零跳过。最终验证版本 1.1.164，下一次迭代 165，使用外部保管的正式 release 身份签名并核对与 1.1.161 一致。覆盖安装保留数据。桌面 runtime JAR、NanoHTTPD 依赖及 launcher classpath 已同步并确认应用窗口正常启动。本任务只推送私有源码备份，不更新公开仓库或 Releases。

后续易用性调整：桌面启动自动共享，退出保留固定转发、停止本地服务；手机保存所选模式，已配对用户升级后自动恢复电脑 GPU 模式。桌面 573 项和 Android 554 项测试再次通过。Android 1.1.165 使用同一正式签名覆盖安装，下一次迭代 166。实际重开桌面软件验证自动监听、Funnel 自动启用和手机公网 HTTPS 鉴权成功；配对码在重开后保持不变。关闭软件后验证本地监听已关闭而转发配置仍保留。手机页面内的模式恢复由设置持久化实现，手动 UI 验收仍需用户完成。

手机「设置 → 放大方式 → RTX（电脑）」会通过现有配对 HTTPS 服务调用电脑 RTX VFX。该服务新增 `/v1/upscale`，仍使用同一 256 位配对密钥；图片限 16 MiB、400 万输入像素，返回 PNG 后删除服务器临时输入文件。实现和首次环境准备见 `RTX_IMAGE_UPSCALING.md`。
